# AGENTS.md

你在这台机器上替 **{{OWNER}}** 干一件具体的事。你会自己判断，这里只讲三件事：**去哪、做什么、怎么交**。

> 这一页是入口，不是说明书。写长了没人读，写虚了会猜。目标是：一个刚醒来的 agent 读完这一页就能开工。

## 三步

1. **同步** —— 拉仓库。先试免密，不通再上 token。token 落在 `.env.local`（`600`，已 gitignore），连接串用完把 remote 改回不带 token 的地址——留着的 token 迟早会跟着 `git remote -v` 漏出去。
2. **看** —— `tasks/*/` 里找 `owner` 指向本机的卡；`entries/` 里已有同 task-id 的 `done` 就跳过。
3. **做** —— 按卡上的「目标」「范围」做。范围是这次的全部地盘；界线外看见的东西交回去，它可能是下一张卡。

**没有指向你的卡 → 静默退出。** 不用报告，不用问一句「需要我做什么」。

## 交作业

做完写一条 entry，四个字段缺一不可：

```
- task: <task-id>
- status: done | blocked
- 正文: 推到哪一步 / 结论 / 卡点
- 产物: <路径或 URL，可机器检查的那种>
```

正文先说结论，再说过程。三行以内。写不进去说明没做完。

## 卡住了

三条通道，选一条：

| 情况 | 怎么做 |
|---|---|
| 卡有歧义、要求互相矛盾、缺关键信息 | `status: blocked`，正文一行 `need: <谁> <要什么>`，然后停 |
| 按卡做完了，但发现更好的做法 | 按卡交，正文加一句「另外发现 X」——那是下一张卡的原料 |
| 发现别的问题（bug、不一致、值得做的事） | 开 issue 说清楚，代码留到有卡的时候再动 |

`blocked` 是有效结果：一份写错的交付，比一次明确的停手贵得多。第四条通道「猜」看着最快，代价最高——猜错的东西没人会去复查，它会一直躺在那儿。

## 边界

界线不是纪律，是这套东西能跑起来的原因：

- **动到的文件 = 卡上范围列出的文件。** 想动别的，先说一句为什么，再回来做——判断留给人，执行留给你。
- **新依赖要卡上允许。** 加一个依赖会改变别人的安装成本，那是派活的人的账。
- **验收条件不动。** 跑不过就是跑不过；放宽条件只是把问题推到下一个人手里。
- **密钥只落在 `.env.local`。** 提交前那次 `git status`，要能解释每一个新文件。

## 自检（交之前）

```bash
./scripts/preflight.sh    # 环境摸一遍：版本、端口、依赖、数据目录
```

跑不过就先交 blocked 并附上输出——那份输出本身就是下一个人最想看的证据。跑过了把最后一行贴进 entry，省他一次重跑。
