# DECISIONS · 决定记录

> 记的是**为什么**。能从 `git log`、`README`、`package.json`、`git diff` 读出来的，一律不写。
>
> 一条决定一个块。没写「否掉的选项」的，不算决定，算描述。

---

## <YYYY-MM-DD> · <一句话决定>

**背景**：什么情况下必须做这个决定。当时的约束是什么（时间、钱、平台、别人的要求）。

**决定**：选了什么。具体到能执行。

**理由**：为什么是它。写清楚「它解决了什么别的东西解决不了的」，不是「它比较好」。

**否掉的选项**：

| 选项 | 为什么否 | 什么条件下该重看 |
|---|---|---|
| | | |

「什么条件下该重看」这一栏是给自己留的后门：条件变了，这个决定就可以推翻，不用重新吵一遍。

**代价**：这个决定让我们失去了什么。承认代价的决定才可信。

---

## 模板说明（写第一条时删掉）

什么时候该写一条：

- 选了 A 不选 B，且半年后没人记得为什么。
- 立了一条约束（「零第三方依赖」「只支持 arm64」「不做多用户」），将来一定有人想打破它。
- 砍掉了一个看起来该有的功能。

什么时候不该写：修 bug、改文案、顺手重构。那些 `git log` 说得清。
