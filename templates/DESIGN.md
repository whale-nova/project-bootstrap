# DESIGN · 现状契约

> **这是契约，不是教程。** 只写「现在什么样、什么不许变、怎么算跑通」。
> 教程会过期且没人管；契约一过期就是 bug，能报出来。
>
> 更新时机：改动了不变量、主链路、验收口径时。**加功能不更新这里，等于没加。**

## 一句话定位

<它是什么，给谁用。一句话。>

**它不做什么**：<三条以内。这一栏比上面那句更能省时间——省掉的是「为什么这里不支持 X」的每一轮讨论。>

## 模块地图

| 文件 / 目录 | 职责 | 不许干什么 |
|---|---|---|
| `src/...` | | |

一个文件一行。职责写不出一个词，说明这个文件该拆了。

## 数据形状

落盘的东西、跨进程的东西、对外的东西，各自的形状和唯一写者。

| 东西 | 位置 | 形状 | 写者 | 读者 |
|---|---|---|---|---|
| | | | | |

**单写者**是这套东西不烂的前提。多个写者就要有锁或版本号，否则迟早互相覆盖。

## 主链路

一次典型请求 / 一条典型流程，从头到尾经过哪几个文件。

```
入口 → A → B → 出口
```

每个箭头后面标一句：这一步失败时，用户看到什么。**看不到任何东西的那一步，就是将来最贵的那一步。**

## 不变量

违反了就是 bug，不是「实现细节」。

1. <不变量> —— 检查方式：<命令 / 单测名>
2. <不变量> —— 检查方式：<...>

写不出检查方式的不变量，要么补检查，要么承认它只是个愿望，删掉。

## 验收口径

怎么算跑通。命令原文 + 期望输出，不写形容词。

```bash
# 最小闭环
<command>          # 期望: <output / exit code>

# 异常路径
<command>          # 期望: <错误信息原文>
```
