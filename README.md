# project-bootstrap

**开工十分钟铺五份文件，让"下一个会话"能接上手，而不是从零考古。**

不是提示词库。提示词搬得走「做什么」，搬不走「什么算对」「环境怎么骗人」「为什么没选另一条路」——这三样只能有实物。

## 它站在哪

市面上那一批（spec-kit、Kiro、BMAD、Agent OS、Backlog.md、superpowers）都在做**「意图 → 计划 → 任务」**：把想法拆成能执行的步骤，保证「照着做能到」。

本仓不做流程编排，只做**物证**：保证「换个人接手，也知道哪里会骗人、哪条决定还活着」。

一句话分工：**他们管怎么干，这里管干完留下什么。**

调研与差异见 [docs/prior-art.md](docs/prior-art.md)。

## 铺

```bash
./bootstrap.sh ~/code/my-thing --name my-thing
# 已有仓库、只想补缺的那几份：加 --only missing
```

生成五份文件，全部是**占位 + 判据**，不是范文。填不进去的地方就删掉那一节——留空比留废话好。

## 五份文件各回答一个问题

| 文件 | 回答 | 谁维护 | 什么时候写 |
|---|---|---|---|
| `AGENTS.md` | 接活的 agent 怎么进来、怎么交、卡住怎么办 | 人 | 开工前，一页 |
| `CARD.md` | 这一件事的目标 / 范围 / 验收 / 失败 | 派活的人 | 每件事一张 |
| `DESIGN.md` | 现在长什么样（不变量、口径、缺口） | 写代码的人 | 第一次提交前 |
| `DECISIONS.md` | 为什么这么定、否掉了什么 | 拍板的人 | 每做一个不可逆决定 |
| `PITFALLS.md` | 哪里会静默骗人 | 被坑的人 | 当场，一条二十字 |

## 三条判据

**1. 能机器检查的，不写散文。**
验收写在散文里的「应该能跑通」等于没写。写成命令 + 期望输出：

```bash
curl -s localhost:8080/health | jq -e '.status=="ok"'   # 期望退出码 0
```

命令跑不了，就说明这件事还没法验收——这本身是个信号，比写完再说强。

**2. 台账只记沉默失败。**
会报错的不记：报错自己会说话，stack trace 里就写着。只记「不报错、但结果是错的」——比如依赖缺文件时静默用随机权重、CLI 的 bin 被包管理器静默丢弃。

这不是偏好，是有数的：对显式报错的标记率约 91%，对「格式正确、值错了」只有 59%。差的这三十多个点没法靠聪明补，只能靠一行行记下来。

**3. 决策必须记否掉的选项，并且有寿命。**
没写否选项的「决定」只是描述。半年后你记得选了 A，忘了为什么不能选 B，然后有人把 B 重新提一遍，讨论从零开始。否选项后面还要跟一句「什么条件下该重看它」。

改主意时不改旧条目，写新的并给旧的标 `superseded by NNNN`——半年后要能一眼看出哪条还活着。

## 四张反模式

- **把成品倒推成步骤清单** → 下一轮产出像执行，不像设计。写判据和验收，别写动作序列。
- **给验收写形容词**（「界面美观」「体验流畅」）→ 无法判定。要么换成可机器检查的条件，要么承认这条不验收。
- **DESIGN 写成教程** → 教程会过期，且过期了没人管。DESIGN 只写现状契约：不变量 + 口径。契约一过期就是 bug，能报出来。
- **台账写成 changelog** → changelog 记「做了什么」，台账记「哪里会骗人」。两者混在一起，台账就没人查了。

## 什么时候别用这套

- 半天能收工的小改。
- 还在探路、连做什么都没定的阶段——那时该写的是一页三条假设，不是五份文件。五份文件是给「已经决定要做」的项目用的。
